

### Coding Guidelines for Agents

When developing agents, it is important to follow certain coding guidelines to ensure that the code is maintainable, efficient, and easy to understand. Below are some key guidelines to keep in mind:
- Use clear and descriptive names for classes, methods, and variables. Avoid abbreviations and single-letter names unless they are widely understood in the context.
- Write modular code by breaking down complex tasks into smaller, reusable functions or classes. This promotes readability, maintainability, and testability.
- Use lombok annotations to reduce boilerplate code and improve readability. For example, use `@Getter`, `@Setter`, and `@ToString` annotations where appropriate.
- Follow the SOLID principles of object-oriented design to create flexible and scalable code. This includes ensuring that classes have a single responsibility, that they are open for extension but closed for modification, and that dependencies are injected rather than hard-coded.
